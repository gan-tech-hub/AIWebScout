# Phase 3: Product UI

## 目的

フェーズ3では、Supabase・OpenAIとの結合前に、実際の利用体験と画面間の情報設計をモックデータで確定する。画面へ業務ロジックを直接書かず、後続フェーズでRepositoryまたはAPIの取得結果へ差し替えられる構成とする。

## 実装画面

- **Overview**: 最近の分析、ページ種別の内訳、平均おすすめ度、Agent pipelineを表示する。
- **Analyses**: キーワード検索、ページ種別・ステータスのフィルター、作成日・スコア順の並び替えを提供する。
- **Agent Workspace**: Browser Capture、処理ノード、Final Insightの3領域で、入力が成果へ変わる過程を表示する。
- **Settings**: ユーザープロフィール、希望条件、AIへの追加指示を入力・検証する。

## UIアーキテクチャ

```text
app/                         ルーティングと画面の組み立て
components/                  AppShellと再利用可能なUI部品
features/analyses/           分析の表示モデル、モック、検索・画面
features/dashboard/          ダッシュボード
features/profile/            設定フォームとZodスキーマ
```

`features/analyses/mock-data.ts` はフェーズ3専用であり、後続フェーズでは同じ表示モデルへAPIレスポンスをマッピングする。検索・並び替えは `filter-analyses.ts` に分離し、単体テスト可能にしている。

## Agent Workspaceの安全性

表示対象は処理名、目的、ステータス、入力・出力の概要、使用ツール、処理時間、警告である。LLMの内部思考、プロンプト全文、Chain of Thoughtは保存・表示しない。画面上の「再分析」はフェーズ3では動作イメージを確認するモックであり、実際のAPI呼び出しは結合フェーズで実装する。

## デザイン方針

- ブランド名、ナビゲーション、状態バッジは英語を維持し、説明や判断情報は日本語で表示する。
- ダークモードを既定とし、端末ローカルにテーマ設定を保存する。
- 半透明パネル、アクセントグロー、状態に意味のあるMotionを用いる。
- `prefers-reduced-motion` を尊重し、キーボードフォーカスと十分なコントラストを維持する。
- デスクトップでは情報密度の高い3カラム、狭い画面では安全に1カラムへ切り替える。

## 動作確認

1. `/` でダッシュボード、テーマ切替、最近の分析リンクを確認する。
2. `/analyses` で検索、フィルター、並び替え、空状態を確認する。
3. `/analyses/demo-job-analysis` でノード選択、詳細切替、根拠の展開、再分析通知を確認する。
4. `/settings` で入力検証と保存通知を確認する。
5. デスクトップ幅とモバイル幅、ダーク・ライトの両テーマで可読性を確認する。

## フェーズ3の境界

このフェーズではDBの読み書き、認証、OpenAI API、リアルタイム更新は行わない。実データ連携後もPresentation層の構造を維持できるよう、モックデータと画面を分離している。
