# Phase 7: MVP Polish

## 目的

全ページ種別の実動作確認で見つかった分析品質と表示上の課題を、内部の構造化契約を維持しながら段階的に改善する。

## サブフェーズ

1. **7-1 Output language**: 入力ページの言語にかかわらず、ユーザー向け分析結果を日本語に統一する。
2. **7-2 Recommendation labels**: ページ種別と推奨スコアに応じてFinal Insightの推奨ラベルを変更する。
3. **7-3 Type-specific presentation**: ページ種別固有の内部キーを日本語ラベルと適切な表示形式へ変換する。

## Phase 7-1: 日本語出力

### 方針

- 英語を含むどの言語のページでも、AIが生成するユーザー向け自然言語は日本語とする。
- 企業名、サービス名、GitHubリポジトリ名、ライブラリ名、技術名、コード、URLは原文を維持する。
- 必要な短い原文引用には日本語の説明を添える。
- `pageType`や`difficulty`などのenum、JSONキー、構造化出力スキーマは変更しない。
- Tool Callingの`reason`も安全な処理ログとして日本語にする。
- 将来の多言語設定を妨げないよう、言語規則はOpenAI adapterの共通プロンプトへ集約する。

### 対象フィールド

- 分類理由
- タイトルと要約
- 重要ポイント、リスク、推奨アクション
- 不足情報
- ページ種別固有結果に含まれる説明文と配列要素
- タグ。ただし技術名・製品名は原文を許容する。
- Tool Callingの理由

### 対象外

- 取得したページ本文の翻訳・保存
- UI言語選択
- 内部キーとenumの日本語化
- 過去に保存済みの分析結果の再翻訳

既存結果は変更せず、新規分析または再分析から日本語出力規則を適用する。

### 検証

- 日本語ページと英語ページの両方で同じ構造化スキーマを通過すること。
- 英語のGitHubページでも、要約、重要ポイント、リスク、推奨アクションが日本語になること。
- 技術名、リポジトリ名、コード、URLが不自然に翻訳されないこと。
- プロンプト単体テスト、型チェック、Lint、全テスト、ビルドを通すこと。
